# Java Blueprints: Комплексный план работ команды (Хакатон Axenix, 48 часов)

> **Цель проекта**: Создание веб-инструмента для разбора монолитного Java-кода (~1000 строк) в интерактивный граф потока управления (CFG/Blueprints), двусторонней синхронизации правок, статического анализа с выявлением узких мест $O(n^2)$, автоматической оптимизации/декомпозиции и подтверждения сохранения поведения (Quality Gate).

## 2. Архитектурный контракт и формат данных

### 2.1. Формат Graph JSON (`/api/graph`)
Граф является **структурным потоком управления (Structured CFG)**. Произвольные переходы запрещены, чтобы избежать генерации недопустимого для Java оператора `goto`. Вложенные блоки (тела циклов, ветки if/else) оформляются через `parentId`.

```json
{
  "methodId": "com.example.Main.processOrders",
  "nodes": [
    {
      "id": "Main.processOrders/entry",
      "type": "method",
      "data": {
        "label": "public List<Order> processOrders(List<Order> orders)",
        "lineStart": 1,
        "lineEnd": 14,
        "hasIssue": false
      }
    },
    {
      "id": "Main.processOrders/s1",
      "parentId": "Main.processOrders/entry",
      "type": "var",
      "data": {
        "code": "List<Order> result = new ArrayList<>()",
        "lineStart": 2,
        "lineEnd": 2
      }
    },
    {
      "id": "Main.processOrders/s2",
      "parentId": "Main.processOrders/entry",
      "type": "condition",
      "data": {
        "condition": "orders == null || orders.isEmpty()",
        "lineStart": 3,
        "lineEnd": 5
      }
    },
    {
      "id": "Main.processOrders/s3",
      "parentId": "Main.processOrders/entry",
      "type": "loop",
      "data": {
        "loopType": "foreach",
        "header": "for (Order order : orders)",
        "lineStart": 6,
        "lineEnd": 12,
        "hasIssue": true,
        "issueId": "iss-nested-complexity"
      }
    }
  ],
  "edges": [
    { "id": "e_entry_s1", "source": "Main.processOrders/entry", "target": "Main.processOrders/s1", "type": "next" },
    { "id": "e_s1_s2", "source": "Main.processOrders/s1", "target": "Main.processOrders/s2", "type": "next" },
    { "id": "e_s2_true", "source": "Main.processOrders/s2", "target": "Main.processOrders/s2_ret", "type": "true" },
    { "id": "e_s2_false", "source": "Main.processOrders/s2", "target": "Main.processOrders/s3", "type": "false" }
  ]
}
```


| № | Задача | Исполнитель | Критерий готовности |
| :--- | :--- | :--- | :--- |
| **1.1** | **Парсер AST в Graph JSON**: интеграция `JavaParser` на `LanguageLevel.JAVA_21`. Построение графа выбранного метода. Любые сложные конструкции оборачиваются в узлы типа `raw` без падений. | D3 | Демо-монолит полностью разбирается в структуру нод и связей. |

## 5. Железные правила команды на 48 часов

1. **Quality Gate — абсолютный приоритет**: если оптимизированный вариант выполняется быстрее, но ломает хотя бы один тест поведения — решение считается недействительным.
2. **Только структурный граф**: никаких перекрестных произвольных связей, нарушающих древовидную семантику языка Java.
3. **Отказоустойчивость демо**: ответы для демо-монолита должны быть заранее закэшированы локально; демонстрация решения жюри не должна зависеть от стабильности внешних LLM API и Wi-Fi в аудитории.
